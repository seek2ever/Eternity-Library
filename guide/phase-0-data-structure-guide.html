阶段 0：统一书籍数据结构

Eternity-Library 数据库线程化重构的第一步

本教程不进行线程重构，也不改变数据库读写职责。我们先解决一个更基础、也更容易被忽略的问题：数据库返回的是元组，表格模型把它变成列表，封面模型又按元组下标读取，多个模块对“一本书长什么样”没有统一约定。

本次操作范围：你将手动新增 book_record.py，然后手动修改两个 Model 和部分查询代码。本文只提供步骤和可运行代码，我不会直接修改项目源码。

适合对象：非计算机专业、正在通过项目学习 Python/PySide6 的业余开发者

本阶段目标：所有模块使用同一种 BookRecord 表示书籍；数据库列名、列顺序和中文表头集中管理。

完成标准：应用可以启动，已有查询和两个视图仍能显示，单独测试脚本可以读取并打印书籍数据。

2. 设计决定：新增一个简单的数据结构模块

我们新增文件 book_record.py，里面只放四类内容：

  1. 数据库字段名的固定顺序。
  2. 字段对应的中文表头。
  3. BookRecord 数据类。
  4. 把 SQLite 查询行转换为 BookRecord 的函数。

这里使用 Python 的 dataclass。它可以理解为“自动帮我们生成初始化方法的数据容器”。它不是数据库，也不是线程，也不会自动做复杂事情，适合当前的学习阶段。

为什么不继续使用数字下标：book[11] 只有作者记得第 11 列是什么时才安全。一旦数据库增加列、查询列顺序改变，程序可能不报错但显示错误数据。使用 book.book_type 更容易阅读和检查。

@dataclass
class BookRecord:
    """表示数据库中的一条书籍记录。"""

    book_id: int | None = None
    book_name: str = ""
    book_path: str | None = None
    add_time: str | None = None
    author: str | None = None
    nationality: str | None = None
    translator: str | None = None
    publisher: str | None = None
    publication_date: str | None = None
    level: str | None = None
    read_status: str | None = None
    book_type: str | None = None
    isbn: int | None = None
    pages: int | None = None
    read_progress: str | None = None
    read_time: float | None = None
    read_date: str | None = None
    read_link: str | None = None
    introduction: str | None = None

    @classmethod
    def from_row(cls, row: Sequence[Any]) -> "BookRecord":
        """把 SQLite 返回的一行数据转换成 BookRecord。"""
        if len(row) != len(BOOK_COLUMNS):
            raise ValueError(
                f"书籍记录应有 {len(BOOK_COLUMNS)} 个字段，实际收到 {len(row)} 个"
            )
        return cls(*row)

    @classmethod
    def from_mapping(cls, values: dict[str, Any]) -> "BookRecord":
        """从字段字典创建 BookRecord，适合扫描结果转成统一对象。"""
        unknown_keys = set(values) - set(BOOK_COLUMNS)
        if unknown_keys:
            names = ", ".join(sorted(unknown_keys))
            raise ValueError(f"发现未知书籍字段：{names}")

        allowed_values = {
            field.name: values[field.name]
            for field in fields(cls)
            if field.name in values
        }
        return cls(**allowed_values)

    def to_row(self) -> tuple[Any, ...]:
        """按数据库字段顺序转换为可用于 INSERT 的元组。"""
        return tuple(getattr(self, column) for column in BOOK_COLUMNS)

    def to_mapping(self) -> dict[str, Any]:
        """转换为字段名到字段值的字典。"""
        return {
            column: getattr(self, column)
            for column in BOOK_COLUMNS
        }


def rows_to_records(rows: Iterable[Sequence[Any]]) -> list[BookRecord]:
    """把多行 SQLite 查询结果转换成 BookRecord 列表。"""
    return [BookRecord.from_row(row) for row in rows]

代码逐段解释

代码作用
BOOK_COLUMNS集中记录字段顺序，后续 SQL、表头和数据转换都可以引用它。
BookRecord一条书籍记录；每个属性对应数据库中的一列。
from_row()把 SQLite 的元组转换成有名字的对象，并检查字段数量。
from_mapping()把扫描模块产生的字典转换成统一对象，并拒绝未知字段。
to_row()写入数据库时按固定顺序生成元组。
to_mapping()需要动态生成 INSERT 列名时，转换回字典。

操作 4：替换 BookQueryWorker 的类型和转换部分

在 BookQueryWorker 中，将原来的 _execute_query 方法整体替换为下面代码：

def _execute_query(
    self,
    sql: str,
    params: tuple = (),
) -> list[tuple] | None:
    """
    在工作线程中执行查询，返回 SQLite 原始行。
    查询失败时返回 None，具体错误由 query_error 发出。
    """
    conn = sqlite3.connect(self.db_name)
    try:
        cursor = conn.cursor()
        cursor.execute(sql, params)
        result = cursor.fetchall()
        cursor.close()
        return result
    except sqlite3.Error as error:
        self.query_error.emit(str(error))
        return None
    finally:
        conn.close()

然后，把 fetch_all_books 整个方法替换为：

@Slot()
def fetch_all_books(self):
    """查询全部书籍，并把每一行转换为 BookRecord。"""
    result = self._execute_query(
        "SELECT * FROM books_information ORDER BY book_id"
    )
    if result is None:
        return

    try:
        books = rows_to_records(result)
    except (TypeError, ValueError) as error:
        self.query_error.emit(f"书籍数据格式错误：{error}")
        return

    self.books_ready.emit(books)

同时，把类顶部的信号注释调整为以下形式：

books_ready = Signal(list)      # list[BookRecord]
query_error = Signal(str)
trigger_fetch = Signal()
为什么把错误改成 None：原代码允许 _execute_query() 返回字符串错误信息，但调用方只判断“是不是 None”。这样字符串可能被当作正常列表传给界面。现在错误立即通过 query_error 发出，成功结果永远是记录列表，含义更清楚。

处理空数据库

注意：空数据库查询成功时，result 是空列表，不是 None。所以必须继续发出 books_ready([])。界面层以后应该清空 Model，而不是直接 if not books: return 保留旧画面。

5. 第三步：让表格模型使用 BookRecord

import sqlite3

from book_record import (
    BOOK_COLUMNS,
    BOOK_COLUMN_TITLES,
    BookRecord,
    rows_to_records,

DB_NAME = "books_information.db"


def main() -> None:
    print("1. 检查字段定义")
    print(f"字段数量：{len(BOOK_COLUMNS)}")
    print(f"表头数量：{len(BOOK_COLUMN_TITLES)}")
    assert len(BOOK_COLUMNS) == 19
    assert len(BOOK_COLUMNS) == len(BOOK_COLUMN_TITLES)

    print("2. 读取数据库实际字段")
    connection = sqlite3.connect(DB_NAME)
    try:
        rows = connection.execute(
            "SELECT * FROM books_information ORDER BY book_id"
        ).fetchall()
    finally:
        connection.close()

    print(f"数据库记录数量：{len(rows)}")
    if rows:
        assert len(rows[0]) == len(BOOK_COLUMNS)
        records = rows_to_records(rows)
        first = records[0]
        assert isinstance(first, BookRecord)
        print(f"第一本书：{first.book_name}")
        print(f"作者：{first.author or '未填写'}")
        print(f"类型：{first.book_type or '未填写'}")
        assert len(first.to_row()) == len(BOOK_COLUMNS)
    else:
        print("数据库目前没有书籍记录，空结果检查通过")

    print("3. 检查字典转换")
    demo = BookRecord.from_mapping({
        "book_name": "阶段0测试书",
        "author": "测试作者",
        "book_type": "测试类型",
    })
    assert demo.book_name == "阶段0测试书"
    assert demo.to_mapping()["author"] == "测试作者"
    print("字典转换检查通过")

    print("阶段 0 数据结构检查全部通过")


if __name__ == "__main__":
    main()

封面模式报 tuple 或属性错误CoverCardModel.set_books 是否已改成接收 BookRecord。
表格能显示但不能编辑BookTableModel.set_data 是否使用 list(book.to_row())，setData() 是否仍修改内部列表。
扫描入库报未知字段打印扫描字典的 keys，判断是拼写错误还是确实需要新增数据库字段。

13. 阶段 0 之后，下一步是什么

完成本教程后，不要立即删除旧的 DatabaseManager 或 BookQueryWorker。阶段 0 的目的只是让它们使用统一的数据结构。下一阶段才是：

  1. 创建一个长期运行的 DatabaseWorker。
  2. 把 SQLite 连接的创建和关闭放到 Worker 所在线程。
  3. 让查询、写入、删除和更新都通过 Qt 信号槽请求。
  4. 让 Worker 发出 list[BookRecord]，主线程更新 Model。
学习重点：阶段 0 不是“为了增加一个文件而增加一个文件”，而是在建立项目中的共同语言。以后看到 BookRecord，就知道它代表一条完整书籍记录；看到 list[BookRecord]，就知道这是可以传递给界面 Model 的书籍列表。
